# 01. Обзор

## Что это

«Опора» (`opora-ui`) — библиотека React-компонентов. Шестнадцать компонентов и пять
«кирпичей», ни одной зависимости, кроме React. Всё поведение — фокус, клавиатура, роли для
скринридеров, позиционирование — написано руками, без Radix и Headless UI. В продукте обычно
берут готовую основу; здесь задача обратная — показать, из чего она состоит.

| Группа | Компоненты |
| --- | --- |
| Действия | `Button`, `Badge`, `Spinner` |
| Формы | `Field`, `Input`, `Textarea`, `Checkbox`, `Switch`, `RadioGroup` + `Radio`, `Select` + `SelectOption` |
| Структура | `Tabs`, `Accordion` |
| Всплывающие | `Dialog`, `Popover`, `Menu`, `Tooltip`, `toast` + `Toaster` |
| Кирпичи | `Slot`, `Portal`, `VisuallyHidden`, `useControllableState`, `computePosition` |

## Запуск

```bash
npm install
npm run dev
```

Откроется Storybook на http://localhost:6010 — он и есть «приложение» для разработки
библиотеки: каждый компонент показан отдельно, во всех состояниях.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Storybook |
| `npm test` | 133 теста |
| `npm run build` | собрать пакет в `dist/` |
| `npm run size` | размер пакета и бюджет |
| `npm run check:package` | проверить `package.json` и типы (`publint`, `attw`) |
| `npm run test:package` | упаковать и «установить» пакет во временное приложение |
| `npm run check` | всё перечисленное подряд |
| `npm run build:storybook` | статический сайт-демо |

## Чем библиотека отличается от приложения

Это главное, что нужно понять, прежде чем читать дальше.

| | Приложение | Библиотека |
| --- | --- | --- |
| Кто пользователь | человек в браузере | другой разработчик |
| Интерфейс | экраны | **API**: имена компонентов, пропсы, CSS-переменные |
| Что собирается | сайт: один раз, целиком | пакет: его потом соберёт чужой сборщик |
| React | в сборке | **не** в сборке — его даёт приложение |
| Изменить название пропса | рефакторинг | **поломка у всех пользователей** → мажорная версия |
| Стили | свои, какие удобно | не должны мешать чужим и должны переопределяться |
| Окружение | известно | неизвестно: Vite, Next, SSR, строгий TypeScript, тёмная тема… |
| Ошибка | исправили и выкатили | исправление доедет, когда пользователи обновятся |

Отсюда всё необычное в проекте: карта `exports`, `peerDependencies`, слои CSS, проверка
упакованного архива, версии по SemVer.

## Принципы

1. **Сначала нативный элемент.** Чекбокс — `<input type="checkbox">`, оформленный CSS.
   Радиогруппа — настоящие радиокнопки в `<fieldset>`. Свои роли — только там, где
   нативного элемента нет (вкладки, меню) или его нельзя оформить (селект).
2. **Клавиатура — по WAI-ARIA Authoring Practices.** Не «как показалось удобным», а как
   ждут пользователи скринридеров.
3. **Управляемый и неуправляемый режим** у всего, что имеет состояние.
4. **Стили не мешают.** Слои + переменные: переопределить можно всё, без `!important`.
5. **Каждое решение объяснено** — в комментарии рядом с кодом.

## Версии

React 19 · TypeScript 7 · Vite 8 (режим библиотеки) · Vitest 5 + Testing Library + axe-core ·
Storybook 10 · Changesets · oxlint.

Пакет рассчитан на **React 19**: `ref` — обычный проп (без `forwardRef`), контекст —
`<Context value>`, чтение — `use()`.
