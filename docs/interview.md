# Шпаргалка к собеседованию

Короткие ответы своими словами, со ссылкой на место в проекте.

## Библиотека и пакет

**Чем разработка библиотеки отличается от приложения?**
Пользователь — другой разработчик, интерфейс — API. Окружение неизвестно (сборщик, SSR,
настройки TypeScript). Изменение API ломает чужой код, поэтому версии по SemVer. React не
входит в сборку. Стили не должны мешать чужим.

**Зачем `peerDependencies`?**
Чтобы React был один — тот, что в приложении. В `dependencies` он мог бы установиться
вторым экземпляром, и хуки перестали бы работать («Invalid hook call»).

**Что такое поле `exports`?**
Карта «импорт → файл» и одновременно ограда: то, чего в ней нет, импортировать нельзя.
Условие `types` должно идти первым.

**Что такое tree-shaking и что нужно от библиотеки?**
Сборщик выбрасывает неиспользуемый код. Нужны ES-модули, `"sideEffects"` в `package.json`
и отсутствие побочных действий при импорте модуля. Помогает `preserveModules` — файл на
компонент.

**Почему библиотеку не минифицируют?**
Это сделает сборщик приложения. Читаемый код в `node_modules` помогает отлаживать.

**ESM и CommonJS — что выпускать?**
Сегодня достаточно ESM. Две версии дают риск «двойного пакета» (два экземпляра состояния).

**Что такое SemVer?**
Мажор — ломающие изменения, минор — новое без поломок, патч — исправления. `^1.2.3`
принимает любую 1.x — поэтому ломать в миноре нельзя.

**Что считается ломающим изменением у UI-библиотеки?**
Удаление и переименование пропсов, смена значений по умолчанию, изменение разметки и имён
классов (на них пишут стили и тесты), повышение версии React.

**Как проверить пакет до публикации?**
`npm pack` и посмотреть содержимое; `publint`; `attw` для типов; установить архив в тестовый
проект и собрать. В проекте — `npm run test:package`.

**Что такое provenance?**
Подпись в npm: из какого репозитория, коммита и workflow собрана версия. Вместе с
доверенной публикацией (OIDC) избавляет от токенов в секретах.

## API компонентов

**Управляемый и неуправляемый компонент?**
Управляемый: значение приходит пропсом, изменения — через колбэк; состоянием владеет
родитель. Неуправляемый: `defaultValue`, состояние внутри. Хорошая библиотека поддерживает
оба — `useControllableState`.

**Что такое составные компоненты (compound components)?**
Несколько компонентов, работающих вместе через контекст: `Tabs` / `TabList` / `Tab` /
`TabPanel`. Гибче, чем один компонент с конфигом: между частями можно вставить свою разметку.

**Что такое `asChild` / Slot?**
Компонент не рисует свой тег, а передаёт классы, обработчики и ref единственному ребёнку
(`cloneElement`). Нужен, чтобы сделать ссылку с видом кнопки или повесить поведение триггера
на свою кнопку — без вложенных интерактивных элементов.

**Как изменился `ref` в React 19?**
Это обычный проп функционального компонента, `forwardRef` не нужен. Следствие: `{...props}`
может перезаписать ref — нужно объединять (`composeRefs`).

**Как дать пользователю отменить поведение компонента?**
Вызвать его обработчик первым и проверить `event.defaultPrevented` перед своим.

**Как переопределять стили библиотеки без `!important`?**
Стили библиотеки — в `@layer`. Стиль вне слоёв сильнее любого стиля в слое.

**Как сделать темы?**
CSS-переменные с именами ролей. Тёмная тема — те же переменные с другими значениями по
`prefers-color-scheme` или атрибуту на предке.

## Доступность

**Что такое дерево доступности?**
Представление страницы для вспомогательных технологий: у узлов роль, имя, состояние,
описание.

**Первое правило ARIA?**
Не использовать ARIA, если есть нативный элемент с нужным поведением.

**Почему `<div onClick>` — плохая кнопка?**
Нет роли, нет фокуса, не реагирует на Enter и Пробел, не объявляется скринридером.

**Как сделать свой чекбокс?**
Оставить настоящий `<input type="checkbox">`, сделать его прозрачным и оформить соседний
элемент через `:checked +`. Не `display: none` — иначе пропадёт из обхода и дерева доступности.

**Что такое roving tabindex?**
В наборе элементов `tabIndex={0}` только у текущего, у остальных `-1`; стрелки переносят
фокус. Tab проходит весь виджет за одну остановку. Вкладки, меню.

**А `aria-activedescendant`?**
Фокус остаётся на одном элементе, а активный потомок указан атрибутом по id. Комбобоксы и
селекты: поле ввода не должно терять фокус.

**Что обязано быть у модального окна?**
`role="dialog"`, `aria-modal`, имя (`aria-labelledby`); фокус внутрь при открытии; ловушка
Tab; остальная страница `inert`; Escape; возврат фокуса при закрытии.

**Что делает атрибут `inert`?**
Делает поддерево недоступным для клика, фокуса и вспомогательных технологий.

**`aria-label`, `aria-labelledby`, `aria-describedby`?**
Первые два дают имя (текстом или ссылкой на элемент), третий — дополнительное описание,
которое зачитывается после имени и роли.

**Что такое живая область (live region)?**
Элемент, изменения в котором скринридер зачитывает сам: `role="status"` (вежливо),
`role="alert"` (сразу). Должна существовать в DOM до появления текста.

**`:focus` и `:focus-visible`?**
Второй срабатывает, когда фокус стоит показать — при управлении с клавиатуры, но не после
клика мышью.

**Как проверять доступность?**
Автоматически (axe) — около трети проблем: имена, роли, ссылки, контраст. Клавиатуру и
фокус — тестами и руками. Понятность — скринридером.

**Почему `disabled` у кнопки с загрузкой — не лучший вариант?**
Элемент выпадает из обхода Tab, фокус теряется. Лучше `aria-disabled` + `aria-busy` и
игнорировать нажатия.

## Всплывающие элементы

**Зачем портал?**
Чтобы всплывающий элемент не обрезался `overflow: hidden` и не зависел от `transform` и
`z-index` предков. В дереве React он остаётся на месте.

**Как решить, кому достаётся Escape, если открыто несколько слоёв?**
Стопка слоёв и один обработчик на `document`: Escape — верхнему, клик закрывает слои выше
того, по которому кликнули.

**Как позиционировать поповер?**
Измерить якорь и элемент, поставить с нужной стороны, перевернуть, если не помещается
(flip), прижать к краю экрана (shift), ограничить высоту доступным местом. Пересчитывать при
прокрутке, изменении размеров. Либо Floating UI, либо CSS Anchor Positioning.

**Как анимировать исчезновение элемента в React?**
Не удалять сразу: оставить в DOM с `data-state="closed"`, дождаться `animationend`, затем
удалить.

**Нативные альтернативы?**
`<dialog>` + `showModal()`, атрибут `popover`, CSS Anchor Positioning.

## Тесты

**Как тестировать компоненты?**
Testing Library: искать по роли и имени, действовать через user-event, проверять то, что
видит пользователь. Не тестировать реализацию (классы, состояние).

**Почему `getByRole` лучше `getByTestId`?**
Тест проходит, только если элемент доступен: есть роль и имя. Доступность проверяется попутно.

**Ограничения jsdom?**
Нет раскладки, стилей, анимаций; фокус на скрытых и `inert` элементах «работает». Геометрию,
контраст и настоящее поведение фокуса нужно проверять в браузере.

**Как тестировать то, что зависит от времени?**
Поддельные таймеры (`vi.useFakeTimers`) и ручная прокрутка времени.

## Про проект — рассказ на минуту

«Библиотека из шестнадцати React-компонентов, написанная без готовых основ вроде Radix:
диалог с ловушкой фокуса и inert, меню и вкладки с навигацией стрелками, селект на
aria-activedescendant, тосты с живыми областями, собственное позиционирование с flip и shift.
Стили — обычный CSS в каскадных слоях и на токенах, поэтому переопределяются без
!important. Пакет — ESM с типами и картой exports; перед публикацией проверяется publint,
attw и установкой упакованного архива во временное приложение с серверным рендерингом.
133 теста через Testing Library с проверкой axe в каждом компоненте; отдельно — сценарии в
настоящем браузере, которые нашли четыре бага, невидимых в jsdom. Демо — Storybook на GitHub
Pages, версии — Changesets, публикация — через доверенного издателя npm без токенов.»
