# 03. Стили

Файлы: `src/styles/tokens.css`, `src/components/*/*.styles.css`.

## Задача

Стили библиотеки должны (1) выглядеть прилично сразу, (2) легко перекрашиваться под бренд,
(3) переопределяться в любом месте без борьбы, (4) не зависеть от инструментов приложения.

Выбор: **обычный CSS** в каскадных слоях, с CSS-переменными. Не CSS-in-JS (тянет рантайм и
плохо дружит с серверными компонентами), не Tailwind (навязал бы его всем пользователям),
не CSS Modules (хешированные классы нельзя переопределить снаружи).

## Каскадные слои

```css
@layer opora.tokens, opora.base, opora.components;

@layer opora.components {
  .op-button { border-radius: var(--op-radius) }
}
```

Правило каскада: **стиль вне слоёв сильнее любого стиля в слое** — независимо от
специфичности селектора.

```css
/* В приложении. Специфичность та же (один класс), но побеждает — потому что вне слоя. */
.my-button { border-radius: 0 }
```

Без слоёв пришлось бы писать `.my-button.my-button` или `!important`, а порядок подключения
файлов решал бы, кто победит. Со слоями библиотека физически не может «перебить» приложение.

Порядок слоёв объявлен один раз, в первой строке `tokens.css`: токены → основа → компоненты.

## Токены

Компоненты не знают цветов — только **роли**:

```css
.op-button[data-variant='primary'] { --_bg: var(--op-accent); --_text: var(--op-accent-text) }
```

Значения ролей — переменные на `:root`. Тема приложения — их переопределение:

```css
:root { --op-accent: #0a8f5b; --op-radius: 4px }
```

| Группа | Переменные |
| --- | --- |
| Поверхности | `--op-bg`, `--op-surface`, `--op-surface-raised`, `--op-muted`, `--op-hover` |
| Текст и границы | `--op-text`, `--op-text-muted`, `--op-border`, `--op-border-strong` |
| Акцент | `--op-accent`, `-hover`, `-text`, `-soft` |
| Состояния | `--op-danger`, `--op-success`, `--op-warning` (+ `-soft`, `-hover`, `-text`) |
| Фокус | `--op-focus`, `--op-focus-ring` |
| Размеры | `--op-radius*`, `--op-control-sm/md/lg`, `--op-text-xs…lg`, `--op-font` |
| Движение и слои | `--op-duration`, `--op-ease`, `--op-z-overlay/popup/toast` |

`--op-control-md` — общая высота кнопки, поля и селекта: поставленные в ряд, они совпадают.

### Локальные переменные

```css
.op-button {
  --_bg: var(--op-surface);
  background: var(--_bg);
}
.op-button[data-variant='primary'] { --_bg: var(--op-accent) }
```

Вариант меняет только переменную; правило `background: var(--_bg)` — одно. Подчёркивание в
имени — знак «внутренняя, снаружи не трогать».

## Тёмная тема

```css
@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) { --op-bg: #121217; … }
}
[data-theme='dark'] { --op-bg: #121217; … }
```

Три режима: системная тема по умолчанию; `data-theme="dark"` — принудительно тёмная;
`data-theme="light"` — принудительно светлая (отменяет системную). Значения написаны
дважды: в CSS нельзя «переиспользовать блок» в медиа-запросе и селекторе одновременно.

Атрибут работает на любом предке — тёмной можно сделать одну панель.

`color-scheme: dark` в том же блоке перекрашивает нативные элементы: полосы прокрутки,
автозаполнение, календарь у `<input type="date">`.

**Контраст — часть темы.** Белый текст на красной кнопке хорош в светлой теме и нечитаем
на светло-красной кнопке тёмной. Поэтому есть `--op-danger-text`: белый в светлой, тёмный в
тёмной. Это нашла автоматическая проверка в браузере — [lessons.md](lessons.md), №6.

## Состояния — через атрибуты

Не классы-модификаторы (`op-button--primary`), а атрибуты:

| Что | Атрибут |
| --- | --- |
| Вариант, размер | `data-variant="primary"`, `data-size="lg"` |
| Открыто / закрыто | `data-state="open"` / `"closed"` |
| Сторона всплывающего элемента | `data-side="top"` |
| Состояния для скринридера | `aria-selected`, `aria-expanded`, `aria-invalid`, `aria-disabled` |
| Нативные состояния | `:checked`, `:disabled`, `:focus-visible` |

Стили привязаны к **тем же атрибутам, что читает скринридер**:

```css
.op-tabs__tab[aria-selected='true'] { color: var(--op-accent) }
```

Если забыть выставить `aria-selected`, вкладка не подсветится — ошибку доступности видно глазами.

## Фокус

```css
.op-button:focus-visible { outline: none; box-shadow: var(--op-focus-ring) }
```

- `:focus-visible`, а не `:focus` — кольцо появляется при управлении с клавиатуры и не
  появляется после клика мышью.
- Кольцо **никогда не убирается без замены**. `outline: none` без альтернативы — самая
  частая причина, по которой сайтом нельзя пользоваться с клавиатуры.
- Кольцо двойное (`0 0 0 2px фон, 0 0 0 4px цвет`) — видно на любом фоне.

## Невидимый, но настоящий `<input>`

```css
.op-checkbox__input { position: absolute; width: 1.25rem; height: 1.25rem; opacity: 0 }
.op-checkbox__input:checked + .op-checkbox__box { background: var(--op-accent) }
.op-checkbox__input:focus-visible + .op-checkbox__box { box-shadow: var(--op-focus-ring) }
```

Input прозрачен, но стоит на месте: получает фокус, клики и читается скринридером.
`display: none` или `visibility: hidden` убрали бы его отовсюду. Нарисованная «коробочка» —
соседний элемент, реагирующий на состояние input через селектор `+`. JavaScript не нужен.

## Движение

- Анимации короткие (120–220 мс) и только `opacity` / `transform`.
- `@media (prefers-reduced-motion: reduce)` — почти мгновенные. Исключение — индикатор
  загрузки: его вращение несёт смысл, оно замедляется, а не выключается.
- `@media (hover: hover)` вокруг `:hover` — на телефоне нет «залипшей» подсветки после касания.

## Высота без JavaScript

Аккордеон раскрывается плавно, хотя `height: auto` анимировать нельзя:

```css
.op-accordion__panel { display: grid; grid-template-rows: 0fr; transition: grid-template-rows 220ms }
.op-accordion__item[data-state='open'] .op-accordion__panel { grid-template-rows: 1fr }
.op-accordion__content { min-height: 0; overflow: hidden }
```

Строка сетки `0fr` имеет нулевую высоту, `1fr` — высоту содержимого, а доли анимируются.

## Мелочи

- Шрифт полей на телефоне — 16px: при меньшем iOS Safari приближает страницу при фокусе.
- Префикс `op-` у всех классов и `--op-` у переменных — чтобы не столкнуться с чужими.
- `:where(...)` в базовых правилах — нулевая специфичность.
- Tailwind 4 в приложении: объявите порядок слоёв до импортов (страница «Темы и стили» в Storybook).

## Ошибки

> **Стили библиотеки без `@layer`.** Пользователю придётся перебивать их специфичностью или
> `!important`, а результат будет зависеть от порядка подключения файлов.
>
> **Цвет в компоненте, а не роль** (`background: #2563eb`). Перекрасить под бренд можно только
> правкой библиотеки. Компоненты знают роли (`var(--op-accent)`), значения — на `:root`.
>
> **Состояние классом из JS** (`className={open ? 'is-open' : ''}`) вместо атрибута, который всё
> равно нужен (`aria-expanded`, `data-state`). Два источника правды расходятся.
>
> **`display: none` у настоящего `<input>` чекбокса.** Он пропадёт для клавиатуры и скринридера.
> Прятать — визуально, оставляя в потоке доступности.
>
> **`outline: none` без замены.** Человек с клавиатурой не видит, где фокус. Стиль фокуса —
> `:focus-visible` с заметным кольцом.

## Попробуйте сами

1. В приложении напишите `.op-button { border-radius: 0 }`. Почему это сработает без
   `!important`, хотя у библиотеки селектор `.op-button[data-variant='primary']` специфичнее?
2. Сделайте тему «бренд»: зелёный акцент и квадратные углы. Какие две переменные?
3. Включите в системе «уменьшить движение» и откройте диалог в Storybook. Что изменилось?

<details>
<summary>Ответы</summary>

1. Стили вне слоёв всегда сильнее стилей в слое — специфичность сравнивается только внутри
   одного слоя.
2. `:root { --op-accent: #0a8f5b; --op-radius: 4px }` (при необходимости ещё `--op-accent-hover`).
3. Анимации появления нет; `usePresence` видит, что анимации нет, и убирает окно сразу.
