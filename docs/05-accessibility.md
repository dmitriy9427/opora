# 05. Доступность

Доступность (accessibility, a11y) — возможность пользоваться интерфейсом без мыши, без
зрения, с увеличением, с дрожащими руками. Для библиотеки это не «дополнительная
фича», а половина работы: `<div onClick>` рисуется за минуту, а кнопка, которой может
пользоваться каждый, — нет.

## Как скринридер видит страницу

Браузер строит из DOM **дерево доступности**. У каждого узла:

| Свойство | Вопрос | Откуда берётся |
| --- | --- | --- |
| **Роль** | что это? | тег (`<button>` → button) или `role="…"` |
| **Имя** | как называется? | текст внутри, `<label>`, `aria-label`, `aria-labelledby` |
| **Состояние** | в каком виде? | `checked`, `disabled`, `aria-expanded`, `aria-selected`… |
| **Описание** | что ещё важно? | `aria-describedby` |

Скринридер читает: «Сохранить, кнопка». «Город, комбинированный список, свёрнут».
«Пароль, поле ввода, недопустимый ввод. Не короче 8 символов».

Посмотреть: DevTools → Elements → вкладка **Accessibility**.

## Первое правило ARIA: не используйте ARIA

Нативный элемент уже умеет всё:

| `<button>` | `<div role="button">` |
| --- | --- |
| роль, фокус, Enter и Пробел, `disabled`, отправка формы | нужно дописать `tabindex`, `keydown` для Enter и Пробела, `aria-disabled`… |

Поэтому в «Опоре»:

| Компонент | Что внутри |
| --- | --- |
| `Button` | `<button>` |
| `Checkbox`, `Switch` | `<input type="checkbox">` (у Switch ещё `role="switch"`) |
| `RadioGroup` | `<fieldset>` + `<legend>` + `<input type="radio">` |
| `Input`, `Textarea` | `<input>`, `<textarea>` |
| `Field` | `<label for>` |

Свои роли — только там, где нативного элемента нет: вкладки, меню, диалог с поведением под
наш контроль, селект с оформлением.

## Клавиатура: два правила

**1. Tab ходит между виджетами, стрелки — внутри.** Меню из 20 пунктов — одна остановка Tab,
а не двадцать.

| Компонент | Tab | Внутри |
| --- | --- | --- |
| Tabs | на выбранную вкладку, затем в панель | ← → Home End |
| RadioGroup | на выбранный вариант | ↑ ↓ ← → (делает браузер) |
| Menu | закрывает меню | ↑ ↓ Home End, буквы |
| Select | выбирает активный пункт и идёт дальше | ↑ ↓ Home End, буквы |
| Accordion | по заголовкам секций | ↑ ↓ (дополнительно) |

**2. Всё, что делается мышью, делается с клавиатуры.** Enter и Пробел активируют, Escape
закрывает.

Техника №1 — **блуждающий tabindex** (roving tabindex): у текущего элемента `tabIndex={0}`,
у остальных `-1`, стрелки переносят настоящий фокус. Так сделаны вкладки и меню.

Техника №2 — **`aria-activedescendant`**: фокус стоит на одном элементе, а «активный»
потомок указан атрибутом. Так сделан селект (глава 07).

## Фокус

- **Виден всегда** (`:focus-visible`, глава 03).
- **Не теряется.** Закрыли диалог — фокус вернулся на кнопку. Удалили строку — фокус
  перенесён на соседнюю. Фокус на `<body>` после действия — баг.
- **Не убегает.** В модальном окне Tab ходит по кругу.
- **Порядок = порядок в DOM.** `tabindex` больше нуля не используется нигде.

## Шпаргалка по компонентам

Шаблоны — из [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/patterns/).

### Button

- `loading` → `aria-busy` + `aria-disabled`, но **не** `disabled`: кнопка остаётся в обходе
  Tab, фокус не «проваливается».
- Кнопка из одного значка обязана иметь `aria-label`.
- `type="button"` по умолчанию.

### Field / Input

- `<label for>` ↔ `id` — связывает `Field` через контекст.
- `aria-describedby` → id подсказки и ошибки (ошибка первой).
- `aria-invalid` при ошибке; текст ошибки — `role="alert"`.
- `required` — атрибутом; звёздочка — `aria-hidden`.

### Checkbox / Switch / Radio

- Нативные; `<label>` вокруг — нажимается вся строка.
- `indeterminate` — свойство DOM, не атрибут.
- Группа радио — `<fieldset>` с `<legend>`.

### Tabs

`role="tablist"` → `role="tab"` (`aria-selected`, `aria-controls`) → `role="tabpanel"`
(`aria-labelledby`, `tabIndex={0}`). Панель в фокусе сама — иначе Tab проскочил бы текст без
ссылок.

### Accordion

Кнопка внутри заголовка (`<h3><button aria-expanded aria-controls>`), область — `<section
aria-labelledby>`. Закрытая секция — `inert`.

### Dialog

`role="dialog"` (или `alertdialog`), `aria-modal="true"`, `aria-labelledby` → заголовок,
`aria-describedby` → описание. Ловушка фокуса, `inert` у остальной страницы, Escape,
возврат фокуса. Заголовок — **обязательный** проп `title`.

### Popover

`role="dialog"` без `aria-modal`; кнопка — `aria-haspopup="dialog"`, `aria-expanded`,
`aria-controls`.

### Menu

Кнопка `aria-haspopup="menu"` → `role="menu"` → `role="menuitem"` / `menuitemcheckbox`
(`aria-checked`). Наведение мыши переносит фокус.

`role="menu"` — для действий. Навигация сайта — `<nav>` со ссылками.

### Select

`role="combobox"` на кнопке (`aria-expanded`, `aria-controls`, `aria-activedescendant`) →
`role="listbox"` → `role="option"` (`aria-selected`).

### Tooltip

`role="tooltip"`, связь через `aria-describedby`. Появляется и по фокусу; Escape скрывает;
на подсказку можно навести курсор (WCAG 1.4.13). Интерактивного внутри нет.

### Toast

`role="status"` (вежливо) или `role="alert"` для ошибок (сразу). Таймер стоит, пока на
уведомлении курсор или фокус. Область существует в DOM заранее.

## Чего автоматика не проверит

`axe` находит около трети проблем: нет имени, неверная роль, битая ссылка на id, контраст.
Он не знает, удобно ли это.

| Проверка | Чем |
| --- | --- |
| Разметка и роли | `axe` в каждом тесте (`expectNoA11yViolations`) |
| Контраст | `axe` в настоящем браузере (в jsdom стили не считаются) |
| Клавиатура и фокус | тесты с `userEvent.keyboard` и `toHaveFocus` |
| «Это вообще понятно?» | руками, со скринридером |

## Проверить руками за пять минут

1. Уберите руку с мыши. Дойдите до каждого элемента и выполните каждое действие.
2. Видно ли, где фокус? Всегда?
3. Увеличьте страницу до 200 % — ничего не обрезалось?
4. VoiceOver (`Cmd + F5`): пройдите форму. Называются ли поля? Зачитываются ли ошибки?
5. Включите «уменьшить движение» в системе — анимации исчезли?

## Ошибки

> **`<div onClick>` вместо `<button>`.** Нет фокуса, нет Enter и Пробела, скринридер не знает, что
> это кнопка. Первое правило ARIA — используйте нативный элемент.
>
> **Кнопка-значок без имени.** Скринридер скажет просто «кнопка». Нужен `aria-label`.
>
> **`role="menu"` для навигации сайта.** Меню — это меню **действий**. Навигация — `<nav>` со
> ссылками.
>
> **`disabled` у кнопки, которая «грузится».** Кнопка выпадает из обхода Tab, фокус
> «проваливается», скринридер не объясняет почему. Для загрузки — `aria-disabled` + `aria-busy`.
>
> **Подсказка только при наведении.** С клавиатуры и на тач-экране её не увидеть: тултип
> открывается и по фокусу.
>
> **Проверили только axe.** Автоматика ловит около трети проблем: порядок фокуса, понятность
> текста, логику клавиатуры она не видит.

## Попробуйте сами

1. Пройдите Storybook «Menu» без мыши. Какими клавишами открыть меню с **последнего** пункта?
2. Включите VoiceOver (`Cmd + F5`) и откройте селект. Что он говорит, когда вы двигаете стрелками,
   хотя фокус остаётся на кнопке?
3. Почему у звёздочки обязательного поля `aria-hidden`?

<details>
<summary>Ответы</summary>

1. Стрелка ↑ на кнопке меню.
2. Название активного пункта: кнопка указывает на него через `aria-activedescendant`.
3. Звёздочка — для глаз; «обязательное» скринридер узнает из атрибута `required` поля. Без
   `aria-hidden` он прочитал бы ещё и «звёздочка».
</details>
