# 06. Всплывающие слои

Диалог, поповер, меню, список селекта и подсказка — самое сложное в любой библиотеке.
У всех одни и те же шесть задач; каждая решена отдельным «кирпичом» в `src/primitives`.

| Задача | Кирпич | Dialog | Popover | Menu | Select | Tooltip |
| --- | --- | --- | --- | --- | --- | --- |
| Не быть обрезанным | `Portal` | ✓ | ✓ | ✓ | ✓ | ✓ |
| Кому Escape и «клик мимо» | `useLayer` | ✓ | ✓ | ✓ | ✓ | свой Escape |
| Встать у кнопки | `usePosition` | — | ✓ | ✓ | ✓ | ✓ |
| Доиграть анимацию закрытия | `usePresence` | ✓ | ✓ | ✓ | ✓ | — |
| Запереть фокус | `useFocusTrap` | ✓ | — | — | — | — |
| Выключить страницу | `useInertOthers`, `useScrollLock` | ✓ | — | — | — | — |

## Портал

```tsx
return mounted ? createPortal(children, document.body) : null
```

Всплывающий элемент рисуется в конце `<body>`, а не там, где написан. Иначе его обрежет
`overflow: hidden` предка, а предок с `transform` станет для него «экраном». В дереве React
он остаётся на месте: контекст и всплытие событий работают.

## Стопка слоёв (`layers.ts`)

Из диалога открыто меню. Нажали Escape — что закрывается? Кликнули по диалогу — что закрывается?

Ответ — стопка. Открылся — лёг сверху.

```
[ диалог ] [ меню ]      ← верх
```

- **Escape** достаётся только верхнему слою.
- **Клик**: находим самый верхний слой, внутри которого кликнули, и закрываем всё, что выше.
  Клик по диалогу закрывает меню, но не диалог. Клик по странице — всё, что закрывается
  кликом мимо.
- Клик по **кнопке, открывшей слой**, «кликом мимо» не считается: она сама его закроет.
  Иначе слой закрывался бы на `pointerdown` и снова открывался на `click`.

Обработчики на `document` — **одни на всю библиотеку**, а не по штуке на каждый открытый
компонент. Десять независимых обработчиков Escape закрыли бы всё разом.

```ts
document.addEventListener('pointerdown', onPointerDown, true)   // capture
```

`capture` — чтобы узнать о нажатии раньше, чем кто-то на странице вызовет `stopPropagation`.
И `pointerdown`, а не `click`: выделение текста, законченное за пределами окна, не должно
его закрывать.

## Ловушка фокуса (`useFocusTrap`)

Только для модального диалога.

1. **При открытии** запомнить `document.activeElement` и перевести фокус внутрь: на элемент
   с `data-autofocus`, иначе на первый доступный, иначе на саму панель.
2. **Tab на последнем** элементе → первый; **Shift+Tab на первом** → последний.
3. **Фокус ушёл наружу не клавишей** (программно, скринридером) → вернуть. Исключение: слой
   выше (меню, открытое из диалога) — это не побег.
4. **При закрытии** вернуть фокус туда, где он был.

`data-autofocus` полезен для подтверждений: фокус ставят на **безопасную** кнопку
(«Не удалять»), чтобы случайный Enter ничего не уничтожил.

## Выключить страницу (`useInertOthers`)

Ловушка держит Tab. Но скринридер умеет ходить по странице и без Tab — «виртуальным
курсором». Чтобы он не вышел из окна, всё остальное получает атрибут **`inert`**:
поддерево недоступно ни клику, ни фокусу, ни дереву доступности.

Алгоритм: идём от окна вверх по DOM и на каждом уровне выключаем «братьев». Остаётся
включённой только ветка с окном. При закрытии — снимаем ровно с тех, кому ставили.

Исключение — `data-op-keep`: область тостов остаётся доступной.

**Порядок хуков важен:**

```ts
useInertOthers(root, dialog.open)   // 1
useFocusTrap(panel, dialog.open)    // 2
```

Очистка эффектов идёт в порядке объявления. Сначала страница перестаёт быть `inert`, потом
ловушка возвращает фокус на кнопку. Наоборот — фокус пытался бы встать на ещё выключенный
элемент и молча уходил на `<body>`. jsdom этого не замечает; в браузере — баг
([lessons.md](lessons.md), №4).

## Блокировка прокрутки (`useScrollLock`)

`overflow: hidden` на `<body>`. Две детали:

- полоса прокрутки исчезает, и страница дёргается вправо — компенсируем `padding-right` на
  её ширину;
- **счётчик**: два окна друг над другом — прокрутка вернётся, когда закрыты оба.

## Позиционирование (`position.ts`)

Расчёт — чистая функция:

```ts
computePosition({ anchor, floating, viewport, placement: 'bottom-start', offset: 8, padding: 8 })
// → { x, y, side, align, available }
```

1. **Поставить**: сторона (`top | bottom | left | right`) + выравнивание (`start | center | end`).
2. **flip**: на нужной стороне тесно, а на противоположной места больше → перевернуть.
3. **shift**: вылезает вдоль стороны → прижать к краю экрана с отступом.
4. **available**: сколько места в выбранную сторону — уходит в CSS-переменную
   `--op-available-height`, и список получает `max-height` с прокруткой.

Хук `usePosition` измеряет элементы (`getBoundingClientRect`) и пересчитывает:

| Когда | Как |
| --- | --- |
| открылось | `useLayoutEffect` — до отрисовки, иначе элемент мигнёт в углу |
| прокрутка любого предка | `scroll` с `capture` (событие не всплывает) |
| размер окна | `resize` |
| изменился размер якоря или элемента | `ResizeObserver` |

Элемент — `position: fixed` с координатами экрана. Пока координаты не посчитаны, он
**прозрачен** (`opacity: 0`), а не скрыт через `visibility: hidden`: скрытый элемент нельзя
сфокусировать, а меню ставит фокус на пункт сразу ([lessons.md](lessons.md), №3).

В браузерах появляется CSS Anchor Positioning — то же средствами CSS. Когда поддержка
станет повсеместной, файл можно будет удалить.

## Анимация закрытия (`usePresence`)

React удаляет элемент мгновенно: `{open && <div/>}` — и анимации исчезновения нет.

```
open = true            present = true    data-state="open"     играет вход
open = false           present = true    data-state="closed"   играет выход
animationend           present = false   элемент удалён
```

Анимация — в CSS по `data-state`. Хук ждёт `animationend` **своего** элемента (события
детей всплывают сюда же). Анимации нет (или «уменьшить движение») — удаляет сразу: проверяет
`getComputedStyle(el).animationName`.

## Собрать всё вместе: `DialogContent`

```tsx
const presence = usePresence(dialog.open)
useLayer({ open: dialog.open, content: root, onDismiss: close, closeOnOutside: false })
useInertOthers(root, dialog.open)
useFocusTrap(panel, dialog.open)
useScrollLock(dialog.open)

if (!presence.present) return null
return (
  <Portal>
    <div className="op-dialog" data-state={presence.state} ref={composeRefs(root, presence.ref)}>
      <div className="op-dialog__backdrop" onPointerDown={() => closeOnOutside && close()} />
      <div role="dialog" aria-modal="true" aria-labelledby={titleId} tabIndex={-1} ref={panel}>…</div>
    </div>
  </Portal>
)
```

Шесть хуков — шесть задач. Каждый можно прочитать и протестировать отдельно.

## А нативные средства?

| Задача | Нативно |
| --- | --- |
| Модальное окно | `<dialog>` + `showModal()`: верхний слой, ловушка фокуса, `inert`, Escape |
| Всплывающая панель | атрибут `popover`: верхний слой, закрытие кликом мимо и Escape |
| Позиционирование | CSS Anchor Positioning |

В новом проекте стоит начать с них. Здесь всё написано руками, чтобы было видно, что
именно они делают, — и потому что нативным пока недостаёт контроля (анимация закрытия,
вложенные слои, поведение фокуса).
