# 07. Разбор компонентов

Шесть компонентов, в каждом — один приём, который стоит унести с собой.

## Select: фокус на кнопке, «курсор» — атрибутом

Файл: `components/select/select.tsx`.

Нативный `<select>` нельзя оформить, поэтому список нарисован свой — и всё поведение
приходится повторить.

```
<button role="combobox" aria-expanded aria-controls="list" aria-activedescendant="option-2">
<div role="listbox" id="list">
  <div role="option" id="option-0" aria-selected="false">Москва</div>
  <div role="option" id="option-2" aria-selected="true" data-active>Казань</div>
```

**Фокус всё время на кнопке.** Пункты списка фокус не получают. Какой пункт «текущий»,
сообщает `aria-activedescendant` — id элемента, который скринридер должен считать активным.
Мы храним индекс (`active`) и рисуем подсветку по `data-active`.

Почему не переносить настоящий фокус, как в меню? У комбобокса фокус должен остаться в
поле: в варианте с поиском человек продолжает печатать. Шаблон один для всех комбобоксов.

Следствие: клик по списку не должен забрать фокус у кнопки.

```tsx
<div role="listbox" onPointerDown={(event) => event.preventDefault()}>
```

**Клавиатура** — одна функция `onKeyDown` на кнопке, две ветки:

| | Закрыт | Открыт |
| --- | --- | --- |
| ↓ ↑ Enter Пробел | открыть | двигать активный / выбрать |
| Home End | — | первый / последний |
| буквы | **сразу выбрать** (как нативный) | двигать активный |
| Escape | — | закрыть без выбора |
| Tab | уйти | **выбрать активный** и уйти |

**Варианты — дети, которые ничего не рисуют.**

```tsx
export function SelectOption(_props: SelectOptionProps) { return null }

const options = Children.toArray(children)
  .filter((child) => isValidElement(child) && child.type === SelectOption)
  .map((child) => child.props)
```

`Select` читает пропсы детей. Так подпись выбранного варианта известна и при закрытом списке
(когда пунктов нет в DOM), а API остаётся декларативным. Цена: варианты должны быть прямыми
детьми — обернуть их в свой компонент нельзя.

**Формы.** Рядом лежит `<input type="hidden" name value>` — значение уходит в `FormData`.

**Field.** `useFieldControl` даёт кнопке `id` (на него смотрит `<label for>`),
`aria-describedby` и `aria-invalid`.

## Menu: настоящий фокус и «наведение = фокус»

Файл: `components/menu/menu.tsx`.

В меню фокус **переносится** на пункты (`tabIndex={-1}` + `element.focus()`): пункты —
самостоятельные действия, а не значения одного поля.

**Навигация без списка элементов.** Меню не ведёт массив своих пунктов. Обработчик на
контейнере ищет их в DOM в момент нажатия:

```ts
moveFocus(event, '[role^="menuitem"]', { orientation: 'vertical' })
```

`getItems` берёт элементы по селектору и отбрасывает выключенные. Пункты можно оборачивать,
группировать, рисовать по условию — порядок всегда совпадает с тем, что на экране.

**Одна подсветка.** Если подсвечивать `:hover` и `:focus` отдельно, после движения мышью и
нажатия стрелки подсвечены два пункта. Поэтому наведение мыши переносит фокус, а стиль
один — `:focus`:

```tsx
onPointerMove: (event) => event.pointerType === 'mouse' && event.currentTarget.focus()
```

**Поиск по первым буквам** (`useTypeahead`): буквы копятся, пока между нажатиями меньше
500 мс; повтор одной буквы перебирает совпадения по кругу.

**С какого конца открывать.** ↓ на кнопке — фокус на первый пункт, ↑ — на последний.
Направление лежит в `ref` (`startFrom`): оно нужно эффекту один раз и не должно вызывать
перерисовку.

**Своё событие выбора.** `onSelect` получает отменяемое событие:

```tsx
<MenuItem onSelect={(event) => { event.preventDefault(); copy() }}>Копировать</MenuItem>   // меню не закроется
```

Для этого создаётся отдельный `new Event('select', { cancelable: true })`. Использовать
исходное событие клавиши нельзя: у него мы сами вызываем `preventDefault` (чтобы Пробел не
прокрутил страницу) — и меню не закрывалось бы никогда ([lessons.md](lessons.md), №1).

## Tabs: блуждающий tabindex

Файл: `components/tabs/tabs.tsx`.

```tsx
<button role="tab" aria-selected={selected} tabIndex={selected ? 0 : -1} data-value={value} />
```

В обходе Tab участвует только выбранная вкладка. Стрелки переносят фокус между вкладками и
(в режиме `automatic`) сразу выбирают:

```ts
const focused = moveFocus(event, '[role="tab"]', { orientation })
if (focused && activation === 'automatic') select(focused.dataset.value!)
```

`activation="manual"` — стрелки только двигают фокус, выбирает Enter или Пробел (это уже
обычный клик по `<button>`). Нужен, когда панель тяжёлая: человек, идущий стрелками от первой
вкладки к пятой, не должен запускать четыре загрузки.

`keepMounted` у панели оставляет её в DOM скрытой (`hidden`) — сохраняются введённый текст и
прокрутка.

## Toast: состояние вне React

Файл: `components/toast/toast.tsx`.

`toast('Сохранено')` вызывают из обработчиков, запросов, вне компонентов. Значит, список
тостов не может жить в состоянии компонента.

```ts
let items: ToastItem[] = []
const listeners = new Set<() => void>()

function show(title, options) { items = [...items, item]; emit() }

// в компоненте
const list = useSyncExternalStore(subscribe, getSnapshot, () => EMPTY)
```

Обычный массив на уровне модуля + подписчики. `<Toaster />` подписывается через
`useSyncExternalStore`. Массив **заменяется**, а не мутируется: хук сравнивает снимки по ссылке.

**Таймер, который умеет стоять.** `setTimeout(dismiss, 5000)` нельзя поставить на паузу.
Поэтому таймер «тикает» раз в 100 мс и вычитает прошедшее время — только если на
уведомлениях нет курсора и фокуса и вкладка видима:

```ts
if (!paused.current && !document.hidden) left -= now - last
```

Оставшееся время сохраняется, а не начинается заново. Это требование доступности
(WCAG 2.2.1): человеку нужно столько времени на чтение, сколько ему нужно.

**Живая область.** `role="status"` — скринридер зачитает, когда договорит текущее;
`role="alert"` (ошибки) — прервётся и зачитает сразу. Область `<section aria-label>`
существует в DOM всегда: скринридер должен знать о ней до появления текста.

**Обновление по id:** `toast('Загрузка…', { id: 'upload' })` → `toast.success('Готово',
{ id: 'upload' })` заменяет тост на месте.

**Правило дизайна, а не кода:** опасное действие лучше сделать обратимым («Удалено —
Вернуть»), чем спрашивать «Вы уверены?». Но критичное в тост прятать нельзя — он исчезнет.

## Tooltip: один ребёнок и пять обработчиков

Файл: `components/tooltip/tooltip.tsx`.

```tsx
<Tooltip content="Удалить"><Button iconOnly aria-label="Удалить">×</Button></Tooltip>
```

Подсказка не рисует обёртку: она клонирует ребёнка и добавляет ему обработчики, ref и
`aria-describedby` (`cloneElement` + `mergeProps` — обработчики ребёнка сохраняются).

| Событие | Действие |
| --- | --- |
| `pointerenter` (не касание) | показать через 400 мс |
| `pointerleave` | скрыть через 100 мс — успеть перевести курсор на подсказку |
| `focus` + `:focus-visible` | показать сразу |
| `blur`, `pointerdown` | скрыть |
| Escape (на `document`) | скрыть |

Проверка `matches(':focus-visible')` — подсказка по фокусу нужна только с клавиатуры: после
клика мышью фокус тоже остаётся на кнопке, но подсказка уже ни к чему.

Касание не показывает подсказку: на телефоне наведения нет, и она мешала бы нажатию.
Вывод для дизайна: **в подсказке не должно быть единственной копии важной информации**.

## Accordion: одна логика на два режима

Файл: `components/accordion/accordion.tsx`.

`type="single"` хранит `string | null`, `type="multiple"` — `string[]`. Внутри значение
всегда массив — а наружу отдаётся в виде, соответствующем режиму:

```ts
onChange: (next) => onValueChange?.(type === 'multiple' ? next : (next[0] ?? null))
```

Типы пропсов — размеченное объединение по `type`: при `type="multiple"` TypeScript требует
массив и не даёт передать `collapsible`.

Закрытая секция остаётся в DOM (ради анимации высоты, глава 03), но с `inert`: её
содержимое недоступно фокусу и скринридеру. Без этого Tab заходил бы в невидимые ссылки.

`headingLevel` — заголовки секций должны быть правильного уровня для **страницы**, а
библиотека не знает, где её вставят.

## Общие мотивы

| Приём | Где |
| --- | --- |
| Состояние, которое не должно вызывать рендер, — в `ref` | `startFrom` в Menu, таймеры в Tooltip, `paused` в Toast |
| Искать элементы в DOM, а не вести их список | Menu, Tabs, Accordion |
| Нативный элемент под стилями | Checkbox, Switch, Radio |
| Контекст для связей между частями | Tabs, Dialog, Menu, Field, RadioGroup |
| id из `useId()` для ARIA-связей | все составные |
| Состояние вне React + `useSyncExternalStore` | Toast, Portal |
